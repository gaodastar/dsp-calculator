# DSP 量化计算器 · 上线方案

> 适用对象：D:\AI\dsp-calculator（纯静态、零后端、零数据库、离线可用）
> 文档状态：v1.0 · 建议按「阶段一 → 阶段二」执行

---

## 1. 现状盘点

| 项 | 现状 |
|---|---|
| 形态 | 纯静态单页应用（HTML/CSS/JS + 174 个 PNG 图标），**无后端、无数据库、无第三方运行时依赖** |
| 产物 | `web/` 目录 179 个文件、约 2 MB（gzip 后 JS 合计约 46 KB，最重的 data.js 仅 26.6 KB） |
| 兼容性 | `file://` 直开可用；任何静态文件服务器均可承载 |
| 数据 | 内嵌 `web/data.js`（dsp-wiki.com 数据快照，游戏版本 0.10.34.28281），页面运行时**不依赖外网** |
| 质量门槛 | 26 项引擎测试 + Web 冒烟 + jsdom 浏览器交互测试，全绿（`npm test`） |
| 版本管理 | ⚠ 尚未初始化 git 仓库 |
| 依赖 | 唯一开发依赖 jsdom（仅测试用），运行时零依赖 |

**结论**：该工具是"教科书级"静态站，上线成本极低，核心工作在于流程化与验收，而非架构改造。

## 2. 上线目标与选型

### 2.1 目标（按优先级）

1. 用户通过一个稳定 URL 访问，加载快（首屏 < 1s），全功能可用；
2. 数据更新（游戏版本更新后）可通过一条流水线完成，无需人工改动业务代码；
3. 出错可一键回滚。

### 2.2 选型对比

| 方案 | 成本 | 国内访问 | HTTPS | 自定义域名 | CI 集成 | 推荐度 |
|---|---|---|---|---|---|---|
| **GitHub Pages**（主站） | 免费 | 一般（建议配合 CDN） | ✅ | ✅ | GitHub Actions 原生 | ⭐ 首选 |
| Cloudflare Pages | 免费 | 较好 | ✅ | ✅ | 原生 | ⭐ 备选 |
| Vercel / Netlify | 免费额度 | 一般 | ✅ | ✅ | 原生 | 可选 |
| 腾讯云 COS + CDN / 阿里云 OSS | 低（按量） | 优秀 | ✅（CDN） | ✅ | 需自建流水线 | 国内主站 |
| 自有服务器 + Nginx | 中等 | 取决于机房 | 需证书 | ✅ | 自建 | 仅在已有服务器时选 |
| 直接分发 zip（网盘/群文件） | 免费 | — | — | — | 手动 | 兜底分发 |

### 2.3 推荐方案（默认执行）

- **主站**：GitHub Pages（仓库开启 Pages，绑定自定义域名，走 Actions 自动发布）；
- **国内加速（可选）**：同一份 `web/` 产物同步推送到 Gitee Pages 或腾讯云 COS + CDN，作为镜像；
- **兜底**：每次发布同时产出 `dsp-calculator-web-vX.Y.Z.zip` 作为 Release 附件，供离线分发。

## 3. 上线前准备（发布门槛）

### 3.1 版本管理

```bash

# .gitignore：node_modules/、.npm-cache/、research/raw/（原始抓取快照不入库，可按需保留）
git add .
git commit -m "v1.0.0: 全物品量化计算器"
git tag v1.0.0
```

### 3.2 构建固化

发布产物 = `web/` 目录本身（data.js/engine.js 为生成文件，**发布前必须用最新数据重建**）：

```bash
npm run build-data   # 重新抓取/生成 data/dsp-data.json（如需刷新数据）
npm run build-web    # 重新生成 web/data.js 与 web/engine.js
npm test             # 26 引擎测试 + 冒烟 + 浏览器交互测试，必须全绿
```

> 注意：`web/app.js` 改动后也必须跑 `npm test`——jsdom 浏览器测试会加载真实页面验证交互。

## 4. 自动化发布流水线（CI/CD）

### 4.1 GitHub Actions（主流程：push 到 main 即发布）

`.github/workflows/deploy.yml` 草稿：

```yaml
name: build & deploy
on:
  push:
    branches: [main]
  workflow_dispatch:
permissions:
  contents: read
  pages: write
  id-token: write
concurrency:
  group: pages
  cancel-in-progress: true
jobs:
  test-and-build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: npm ci --ignore-scripts        # 仅测试依赖 jsdom
      - run: npm run build-web              # 固化 data.js / engine.js
      - run: npm test                       # 门槛：不绿即阻断发布
      - uses: actions/upload-pages-artifact@v3
        with: { path: web }
  deploy:
    needs: test-and-build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

### 4.2 数据刷新流水线（游戏更新后手动触发）

`data-refresh.yml`：`workflow_dispatch` 触发 → 运行 `research/build-data.mjs`（重新抓取 dsp-wiki protosets.json）→ 跑测试 → 若全绿则提交 PR（不直接合入），人工确认数值后合并。

> 由于 dsp-wiki 数据接口稳定（`Module:GameData/protosets.json`），刷新成本约 5 分钟；图标缺失时再跑 `npm run fetch-icons`。

### 4.3 国内镜像同步（可选）

主站发布成功后，同一 workflow 追加一步：把 `web/` 上传到腾讯云 COS（`coscmd` 或官方 action），实现国内外双入口。两个入口共用同一份构建产物与版本号。

## 5. 域名、HTTPS 与缓存策略

### 5.1 域名

- 短域名优先（如 `dsp-calc.example.com`），与主站用途一致；
- 自定义域名接入后启用 HTTPS（GitHub Pages 自动签发 Let's Encrypt 证书，强制 HTTPS）。

### 5.2 缓存与压缩（自有服务器 / CDN 场景）

Nginx 关键配置：

```nginx
server {
  listen 443 ssl;
  server_name dsp-calc.example.com;
  root /srv/dsp-calculator/web;
  index index.html;

  gzip on;
  gzip_types text/css application/javascript image/svg+xml;

  location ~* \.(png|js|css)$ {
    expires 30d;
    add_header Cache-Control "public, immutable";
  }
  location /index.html {
    add_header Cache-Control "no-cache";   # 保证发版后立即生效
  }
}
```

> 版本化文件（data.js 等）内容变化时才变，`immutable` 缓存是安全的；页面本身 no-cache 即可。

## 8. 监控与运维

- **可用性**：GitHub Pages 自带基础监控；国内镜像可用腾讯云/阿里云拨测（免费额度足够）；
- **数据新鲜度**：页面 footer 显示游戏版本号，用户可自行比对；游戏发新版后触发 4.2 流水线；
- **回滚**：GitHub Pages 无热回滚，直接 `git revert` 合并 + 重新触发流水线即可（全程 < 2 分钟）；Release 附件保留历史版本；
- **问题反馈**：README/页脚放 Issues 链接，收集配方数值纠错（用 dsp-wiki 页面做仲裁）。
